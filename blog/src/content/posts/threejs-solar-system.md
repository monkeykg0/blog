突发奇想，想要一张"很炫酷的太阳系运行图"：太阳、八大行星、月球，都按轨道跑起来。听起来是个一下午的小玩具，实际做了三版才对味——前两版 2D Canvas 全部推翻，最后换 Three.js 真 3D 才出效果。

先放成品：**[寰宇星图 · 太阳系 3D](/demo/solar-system.html)**（单 HTML 文件，1.4MB，无任何外部依赖）。可以拖拽环绕、滚轮推近到行星表面、点击任意天体让镜头飞过去跟随它公转。建议点一下土星。

这篇记录三版方案差在哪，以及真 3D 版的几个关键实现。

## 第一版：2D Canvas 示意图（失败）

最直觉的做法：Canvas 上画同心椭圆轨道，行星是径向渐变的小圆，按真实相对周期转（水星 88 天最快、海王星 164.8 年最慢），配上毛玻璃控制面板。

功能都对——播放/暂停、速度、点击弹信息卡、月球绕地球。但看一眼就知道问题：**这是教科书插图，不是宇宙**。行星是"画出来的球"，背景是"撒了点白点的黑布"，没有任何纵深。

## 第二版：2D 贴图映射 + 程序化银河（还是失败）

第二版下了狠功夫：

- 下载了 [Solar System Scope](https://www.solarsystemscope.com/textures/)（CC-BY 4.0）的真实行星贴图，用**经度切片映射**把等距圆柱投影贴图裹到 2D 圆上模拟球体自转——把贴图按 `asin` 切成几十条竖片，每片采样对应经度，贴图滚动就是自转
- 程序化生成斜贯全屏的银河带：2600 颗星尘 + 云雾 + 暗尘埃裂隙
- 晨昏线、临边昏暗、大气辉光、小行星带、流星、黄道光……全堆上了

结果依然不对。单看每个元素都还行，合在一起还是一张"精致的平面图"。复盘下来核心问题就一个：

> **2D 模拟 3D 有硬上限。** 光照是画的、遮挡是排序出来的、"纵深"是椭圆压扁装的。镜头不能动，视差就不存在；视差不存在，浩渺感就无从谈起。宇宙的震撼来自空间本身，而我在纸上画空间。

方向错了，细节堆得再多都救不回来。推翻。

## 第三版：Three.js 真 3D（成了）

换 WebGL 之后，前两版拼命"画"的东西全部免费获得：

- **真实光照**：太阳位置放一个 `PointLight`，每颗行星的晨昏线、球面明暗是光照方程自然算出来的，不用画
- **真实遮挡**：深度缓冲解决，不用排序
- **真实视差**：镜头一动，银河穹顶、远景星点、行星之间的相对位移立刻让空间"立"起来

### 单文件的约束：全部内嵌

我要的是一个双击就能打开的单 HTML，不依赖 CDN。这带来两个问题：

**Three.js 版本选择。** 新版 Three.js 只发 ES Module，`examples/jsm` 里的后期处理链（EffectComposer/UnrealBloomPass）全是模块导入，单文件内嵌很麻烦。解法是用 **r147**——这是最后一个同时提供 UMD 构建（`three.min.js`）和非模块版 `examples/js` 的版本（r148 删掉了 `examples/js`）。九个文件按依赖顺序串进 `<script>` 就行，唯一的坑是加载顺序：`EffectComposer.js` 里定义了 `THREE.Pass` 基类，必须排在其他 Pass 前面。

**贴图内嵌。** 十一张贴图（八行星 + 太阳 + 月球 + 银河全景）+ 土星环条带，全部 `sips` 压到 512~2048 宽、JPEG 质量 50-60，base64 后约 700KB：

```bash
# 主角行星 1024x512，配角 512x256，银河穹顶 2048x1024
sips -z 512 1024 -s format jpeg -s formatOptions 60 jupiter.jpg --out small/jupiter.jpg
base64 -i small/jupiter.jpg   # 拼进 JS 对象
```

最终整个文件 1.4MB：Three.js 630KB + 贴图 700KB + 自己的代码。

### 泛光：太阳必须"烧"起来

炫酷感一半来自 bloom。太阳用 `MeshBasicMaterial`（自发光不受光照），把颜色乘到超过 1 触发泛光阈值：

```js
sunMesh.material.color.setRGB(1.6, 1.35, 1.05); // 推高亮度
const bloom = new THREE.UnrealBloomPass(
  new THREE.Vector2(W, H),
  1.05,  // strength
  0.55,  // radius
  0.62   // threshold：太阳和亮星过阈值发光，行星保持锐利
);
```

阈值 0.62 是调出来的：再低行星亮面也开始泛光糊掉，再高太阳就不够"炸"。

### 天体参数：能真实的都真实

尺寸和轨道距离必须压缩（真实比例下水星是个像素都不到的点），但**所有周期和姿态用真值**：

- 公转周期严格 1 : 0.241 : … : 164.8，肉眼能看出水星狂奔、海王星几乎不动
- 自转周期同样按真值缩放：木星 9.9 小时最快，**金星和天王星逆向自转**
- 轴倾角：地球 23.4°，**天王星 97.8° 横躺着滚**
- 月球潮汐锁定：自转角直接绑公转角，永远同一面朝地球
- 2600 颗小行星按开普勒第三定律 `ω ∝ r^-1.5` 差速运转，内圈追着外圈跑

### 镜头跟随：交互的灵魂

点击天体后镜头飞过去并持续跟随，是整个 demo 最值的一个功能。实现比想象中简单——`OrbitControls` 的 `target` 每帧向天体位置插值，镜头自然被拖着走，同时用户还能自由环绕：

```js
// 每帧
if (selected) {
  bodyWorldPos(selected, vec);
  controls.target.lerp(vec, 0.14);   // 跟随公转中的行星
}
// 点击时额外做一段 easeOut 推镜
camTween = { from: camera.position.clone(),
             to: vec.add(dir.multiplyScalar(size * 6.5)), t: 0, dur: 1.4 };
```

跟着土星公转、随手一拨镜头绕到光环背光面的时刻，前两版差在哪就非常具体了。

### 拾取的小坑

行星在屏幕上可能只有几个像素，直接对本体 mesh 做 Raycaster 拾取基本点不中。解法是给每个天体加一个放大 1.9 倍的隐形代理球，射线只打代理：

```js
const hit = new THREE.Mesh(
  new THREE.SphereGeometry(Math.max(size * 1.9, 2.4), 12, 8),
  new THREE.MeshBasicMaterial({ visible: false })
);
```

顺便记一个 2D 版就踩过的：`pointerup` 时要判断位移 < 6px 才算点击，否则拖拽结束会误触选中。

## 收尾

三版下来最大的教训不是任何一个技术点，而是：**审美目标决定技术路线，路线错了，执行力是负资产**。第二版我在 2D Canvas 上堆了银河、星云、流星、黄道光十几种效果，每一样都白费；第三版换了正确的地基，一半的功能量就到位了。

下次再有"做个炫酷的 XX"这种需求，先问一句：它的震撼感来自哪里？如果答案是"空间"，那从第一行代码起就该是 3D。
